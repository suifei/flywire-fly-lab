## What this is

A research workspace (not a git repo) for reproducing Eon Systems' "digital fly brain" and connecting it to a simulated body. It wraps two upstream projects rather than reimplementing them:

- `external/fly-brain/` — official clone of `github.com/eonsystemspbc/fly-brain` @ `a3db62f` (GPL-2.0-or-later). Whole-brain LIF model (Shiu et al. 2024) on FlyWire v783: 138,639 neurons, 15,091,983 weighted edges, dt = 0.1 ms. Treat as read-only upstream.
- FlyGym 2.1.0 (EPFL NeuroMechFly v2, MuJoCo 3.9) installed as a pip package in the `flygym` env — provides body, 3D world, compound-eye vision.
- `external/flywire_annotations/Supplemental_file1_neuron_annotations.tsv` — public FlyWire cell-type annotations (`root_id`, `cell_type`, `side`, …), used to label neurons and select them by type. Codex (codex.flywire.ai) requires Google login, so this file is the substitute.
- `external/Fly-Brain-AI/` — clone of community project `neilt93/Fly-Brain-AI` @ `64bdbaf`: a Brian2 whole-brain ↔ FlyGym 1.2.1 closed loop, with the looming experiment replicated here. **No license**, so run it locally but never copy its code into our deliverables or redistribute it; our scripts only import it. Two local repairs were needed:
  - Its `brain-model` submodule has no `.gitmodules`, so `philshiu/Drosophila_brain_model` @ `91bdd1e` was cloned into `external/Fly-Brain-AI/brain-model/` by hand. Its `Connectivity_783.parquet` is byte-identical to Eon's (same SHA-256).
  - Gitignored `plastic-fly/data/*_v4_looming.npy` files are regenerated by `fba_reconstruct_ids.py`.
- `external/Pugliese_cpg_2025/` — clone of `github.com/smpuglie/Pugliese_cpg_2025` @ `faee4b0` (Pugliese et al. 2025 VNC rate model + MANC/FANC/BANC T1 data). **No license**: import only, never copy code. Its `configs/paths/*.yaml` hold the authors' cluster paths; `vnc/run_pugliese.py` builds the OmegaConf config itself with a local `data_dir` instead of using Hydra path templates.

User-facing docs are in Chinese: `docs/log/report.md` (findings, verified results, error log, licenses) and `embodiment_plan.md` (routes A/B/C). Keep new user-facing text in Chinese and keep the 【官方】/【社区】/【实测】/【推测】 labeling convention (official / community / measured / inference); never report results that were not actually run.

## Environments (separate conda envs; they cannot be merged)

`setup.sh [cpu|gpu|flygym]` builds them. `gpu` follows the official README and is untested here.

- `brain-fly-cpu` — Python 3.10, numpy 1.26, brian2 2.9, **pytorch from conda-forge**. Do not `pip install torch` here: it causes `OMP: Error #15` (duplicate libomp with conda-forge llvm-openmp).
- `flygym` — Python 3.12, numpy 2.x, flygym 2.1.0, plus pip torch/pandas/pyarrow (no OMP conflict in this env). Used for anything touching FlyGym, including the connectome closed loop.

- `fba` — Python 3.11, flygym **1.2.1** (old Gymnasium API, mujoco 3.2.7, dm_control), brian2 2.9, cython. Used only for Fly-Brain-AI and `fba_*.py`. Not in `setup.sh`; it was created with `conda create -n fba python=3.11 && pip install "flygym==1.2.1" brian2 cython pandas pyarrow h5py imageio imageio-ffmpeg pyyaml matplotlib scipy`.

- `fba` also has flyvis 1.2.0 + torch (pip). Its pretrained models live in `site-packages/flyvis/data/results/flow/0000/000`. The official `download_pretrained_models` timed out (httplib2 ignores the proxy), so they were fetched with curl from the same Drive API endpoint; the SHA-256 matched.
- `flybody` — Python 3.11, flybody (git), mujoco 3.13, dm_control 1.0.46, numpy 1.26. Used only by `flight/export_flight.py`; run it with `MUJOCO_GL=glfw`. Also used by `scratch/probe_rl_speed.py`.
- `flybody-tf` — clone of `flybody` plus tensorflow 2.16.2, tensorflow-probability 0.24.0, tf-keras 2.16.0 (flybody's `[tf]` extra pins TF 2.8/reverb, which have no macOS arm64 wheels). Used only by `flight/policy_rollout.py`. The trained policies (TF 2.8/TFP 0.16 SavedModels returning a TFP distribution) load only after `flight/tfp_compat.py` aliases the old full-path TypeSpec names (`tensorflow_probability.python.distributions.independent.Independent_ACTTypeSpec` → `tfp.distributions.Independent_ACTTypeSpec`).
- `vnc-sim` — Python 3.13, JAX 0.9.2 (CPU only), diffrax 0.7.0, hydra/omegaconf; created from `external/Pugliese_cpg_2025/environment.yaml` (`conda env create -f …`, which also `pip install -e` the repo). Used only by `vnc/run_pugliese.py`.

`import pyarrow` must precede `import torch` (upstream note about a libarrow conflict).

## Memory safety — read before running anything

The dev machine is a 16 GB M1 Pro and has frozen once from OOM. Normal runs peak at 2.5–4.3 GB; this includes the Fly-Brain-AI real-brain looming run, despite its README claiming ~8 GB. Rules:

- Run one simulation at a time; never launch experiments in parallel.
- Wrap runs with `scratch/memguard.sh <limit_MB> <logfile> cmd...`, which kills the process tree over the limit and appends `exit=… peak_tree_rss_MB=…` to the log.
- The cause of the freeze: upstream `poi()` creates one `PoissonInput` per stimulated neuron, so Brian2 cpp_standalone generated 8,248 code objects and compiled them with unbounded `make -j`. `run_experiment.py` guards this (`MAX_POISSONINPUT = 50` → single `PoissonGroup` + one-to-one `Synapses`; `extra_make_args_unix = ["-j4"]`). Preserve these guards when editing.
- Ask the user before starting long or large runs; they have explicitly asked to be consulted when memory is a concern.

## Architecture

**Brain backends in `run_experiment.py`** import upstream code instead of copying it:
- `brian2` (default; fastest on CPU, ~2.5 s per simulated second): uses `code/paper-phil-drosophila/model.py` (`create_model`, `poi`, `silence`) under `cpp_standalone`. Build once into `results/.brian2_build`, then `device.run()` per trial. Standalone mode can't read `syn.i` or assign by index array before build, which is why bulk silencing rebuilds weights from the parquet and `neu.rfc` is assigned as a whole array.
- `torch`: uses `code/run_pytorch.py` `TorchModel`/`MODEL_PARAMS`. The weight matrix is built directly from the parquet as sparse `(post, pre)` with values `Excitatory x Connectivity`. MPS does not support CSR, so on `mps` a subclass swaps only the recurrent `matmul` for `torch.sparse.mm` on a COO tensor.
- Silencing matches upstream code semantics: outgoing synapses of the neuron set to 0. The upstream README claims "to and from", but the code does not do that.

**Closed loop (`connectome_vision_loop.py`)**: every 15 ms window:
1. Read compound eyes with `sim.get_ommatidia_readouts` → `(2 eyes, 721 ommatidia, 2 channels)`.
2. Hand-written looming feature → Poisson rates on LC4 left/right.
3. `ConnectomeBrain.run_window` advances `TorchModel` 150 steps, accumulating readout spike counts on-device.
4. Map DNa01/DNa02 (steer), DNg97 = oDN1 (forward), DNp01 = Giant Fiber (freeze placeholder) → `HybridTurningController.step([L, R], obs)` → 150 physics steps (timestep 1e-4 s).

Brian2 can't be used here because standalone cannot change inputs mid-run. The visual front end (`LoomingFrontEnd`) and the DN→drive mapping are hand-written assumptions. `LoomingFrontEnd` calibrates a sky-only upper-visual-field mask with the ball hidden, then computes low-pass-filtered, deadbanded growth of the dark fraction. This fixes the earlier bug where the fly's own legs in the lower field triggered false LC4 input. **Validated 2026-09-16** (report §26, `python vision/frontend_check.py <log.csv>` applies 4 pre-declared criteria): with `--frontend-only --duration 1.0`, the sky mask calibrates to 244/291 ommatidia per eye and the dark fraction is **exactly 0** for the first 0.495 s, so LC4 stays at 0 Hz while the ball is far (old front end hit 200 Hz at 0.045 s); the real looming signal survives (21.4 Hz mean in the last 0.2 s). **But the validation exposed a separate defect: `lc4_gain` was never calibrated** — LC4 jumps to a saturated 200 Hz at a 0.4% dark fraction and stays there to 99%, so it takes only the values 0 or 200 with 6 on/off flips. **That gain is now calibrated** (§27, one pre-declared run): measured expansion has median 1.92 and p95 10.11 (dark-fraction/s), so rule A gives `gain = 200 ÷ p95 = `**`19.8`** — the old hand-picked 4000 was **202× too high**. New default is 19.8; all criteria pass, saturation 23%→2%, flips 6→1, and LC4 now takes **15 distinct values instead of 2** (Spearman 1.000 with expansion). **The deeper lesson is a tooling one: the log recorded only the post-`clip` LC4, never the pre-clip `expansion`, so a 200× parameter error was invisible in the data** — LC4 merely looked reliably responsive. Anything that gets clipped, saturated, or normalized must be logged *before* that step too; the script now logs `exp_L`/`exp_R`. Behavior with the brain loaded is still not validated.

**Fly-Brain-AI loop** (`plastic-fly/bridge/`), one cycle per `brain_dt` window:
1. `FlyGymAdapter` turns the FlyGym 1.x obs dict into a `BodyObservation`.
2. `SensoryEncoder` produces Poisson rates for the sensory IDs, mapped by ID via `_id_to_idx`, so array order is irrelevant.
3. `Brian2BrainRunner` runs Brian2 **runtime** mode incrementally, with a `PoissonGroup` input and the network rebuilt each trial.
4. `DescendingDecoder` takes group mean rates and applies tanh → `LocomotionCommand`.
5. `LocomotionBridge` (CPG) → `sim.step`.

The looming experiment writes a fixed `looming_intensity` into LPLC2 rates; no visual scene is involved.

`fba_export_replay.py` replicates `run_looming_trial` using those same bridge classes. It additionally records 69 mesh-geom world poses every 25 body steps, plus per-window group rates and commands. It exports vertex-clustered meshes (248k → 34k verts) for the three.js viewer. MuJoCo quats are `(w,x,y,z)`; three.js needs `(x,y,z,w)`. World axes: +x initial heading, **+y = fly's left** (verified: `LFCoxa` y = +0.17), +z up, units mm.

**Dodge game layers** (`dodge/`):
- `subcircuit.py` selects neurons with (hops from LC4/LPLC2) + (hops to DNa01/DNa02/DNp01) ≤ K over edges with ≥ wmin synapses, then keeps all induced edges. It holds the numpy reference simulator, which mirrors Brian2's schedule: state update → threshold → delayed synapses and Poisson → reset.
- `brain.js` is the same scheme as an event-driven JS engine; `parity_test.js` must keep it matching the Python reference.
- `game_core.js` is render-free and holds every hand-written rule: dθ/dt looming front end, lead-aimed balls (a non-reacting fly is always hit), DNa → turn mapping, GF threshold → vertical takeoff. It is shared by the page and `autoplay.js`.
- Lesions: LC4/LPLC2 = zero outgoing synapses. GF/DNa are output neurons, so silencing their outgoing synapses would do nothing; their lesions zero the motor readout instead.
- Don't tune hand-written rules to produce a desired lesion result. A forward-jump rule was replaced by vertical takeoff because jump direction confounded the turning comparison.

**Game v2 rules in `game_core.js`** (all defaults reproduce v1; the page overrides them):
- Encoding options: `encoding: "ache2019"` makes LC4 ∝ angular velocity and LPLC2 = Gaussian(angular size). The form follows Ache et al. 2019; the parameters were hand-picked (paper full text unavailable).
- GF readout uses `gfTau` (0.02 s).
- `takeoff: "clip"` flies a real evasion clip set via `setFlightClips`. It picks the turn away from the threat and rotates the clip to point away from it (Card & Dickinson 2008). The page renders the flybody mesh with wing poses per frame, with optional ×0.08 slow motion (brain and world slowed together).
- Flyaway modes make dodge ≈ 99–100% regardless of encoding. Encoding only matters under `hop`, where takeoff timing is everything.
- Flight clips: `export_flight.py` wrongly included the task's `ghost` reference fly (81 extra meshes, legs not retracted) in `meshes`; `policy_rollout.py` exports walker meshes only (85). Controller rollout inputs are the 9 `walker/*` observables of the policy signature; actions: head 0–2, wings 3–8, abdomen 9–10, user 11 (wingbeat frequency). Tracking vs recording: median 0.26/0.30 mm, but the left clip diverges to ~7 mm / 50° in its last ~30 ms. No public Drosophila takeoff kinematics were found (FlyPEZ/Dombrovski 2023 takeoff data on request only; Fontaine 2009 none), so takeoff/landing stay hand-written.
- Flight display: game steps are 5 ms but clip frames are 0.4 ms and a wingbeat is 4.6 ms, so rendering `S.clipFrame` strobes (wings nearly frozen). The page renders `FlyDodgeGame.clipPose(clip, CFG, origin, jumpDir, S.jumpT + carry)` every animation frame instead (step() uses the same helper; verified identical game states). Slow motion is ×0.04; at 1× the page draws 3 translucent ghost wing groups. Only body pose is recorded data; wings are flybody's symmetric base pattern; takeoff/landing are hand-written.

**v3 abilities**:
- `game_core.js` enables them only when SUB has the v2 groups (`G.V3`): contact → SUGAR/BITTER rates, dust → JO, looming velocity → LC16. Readouts MN9/aDN1/MDN with thresholds 30/20/20 Hz; state priority fly > back > feed > groom > walk.
- `brain.js` reads input groups from `SUB.meta.inputs`. v1 hardcoded LC4/LPLC2, and new inputs silently did nothing.
- Lesions on inputs silence synapses; lesions on MN9/aDN1/MDN zero the readout.
- VNC: `vnc/build_banc_vnc.py` writes BANC in fly-brain file format under `external/banc_vnc/`; `run_experiment.py` runs it via `FLY_BRAIN_REPO`.

**v6 additions (physics world + real-neuron knockouts + water)**:
- `brain.js` gained `setSilencedNeurons(name, idx, on)` / `rebuildWeights()` (arbitrary neuron sets, same semantics as the full-brain screen) and `setRateNeurons(idx, hz)` (Poisson drive on an arbitrary index list, not a named group).
- `game_core.js`: `G.NEURONS` = 10 real neurons from the §14–24 screens, each with its in-subcircuit MN9 ratio *and* the full-brain value (they disagree — say so on the page); `G.setNeuronLesion(key, on)`. Wind (`windStep`) drives the JO groups; `light` scales the visual front end; `G.speech()` builds a sentence from real firing rates with hand-written thresholds + templates.

Measured in-game with the pellet under the head, 3 seeds: **sugar drives MN9 to 82.9 Hz, water only 14.1 Hz**. Thirst is hand-written (+0.06/s, −0.5/s while drinking); the drinking threshold is `feedThreshold * max(waterThreshRatio, 1 - thirst)` = 30 Hz → 3.6 Hz when thirsty, so a sated fly walks past water and a thirsty one drinks. Rationale (the paper uses pseudodessicated flies) is hand-written — this LIF model has no internal state.
- `CFG.pelletTypes` (default `["sugar","bitter","mixed"]`, page sets `[..., "water"]`) keeps the auto-pellet cycle configurable so `step_v3.js`'s published numbers stay reproducible.
- **The subcircuit reproduces the full-brain knockout pattern on both pathways, water somewhat better** (§25.2, exploratory, n=10): game-vs-full-brain Pearson **+0.75 sugar / +0.89 water** (Spearman 0.58 / 0.84; median abs diff 0.24 / 0.11), all 10 neurons, one protocol on both sides. Phantom is the clearest single case: knocking out this GABA neuron multiplies MN9 by **3.02 in the full brain and 2.06 in the game**. Biggest distortion is CB0883: a hub in the full brain (0.76 alone, 0.24 when paired) but inert in the subcircuit (1.07), because its bypass routes are what wmin ≥ 3 / K ≤ 3 removes.
  - **An earlier version of this claimed "+0.21 sugar / +0.92 water — the subcircuit only reproduces water". That was wrong**, from mixing protocols (sugar un-normalized, water null-normalized) and using only the 6 paper-named types. The "pruning preserves concentrated pathways and destroys distributed ones" story is only weakly supported at n=10; don't state it as a conclusion.
  - Two commands keep these numbers reproducible and on one protocol: `node dodge/measure_neurons.js` (subcircuit) and `python dodge/measure_neurons_fullbrain.py` (full brain, recomputed from the stored segments — joint knockout of every ID the page's toggle silences, null-median-normalized, 6 realizations). `G.NEURONS`' `full`/`fullWater`/`fullAdn1` come from the latter; never hand-copy them from report prose again.
- **`node --check` passing does NOT mean the page works.** On 2026-09-16 three `` `a``b` `` pairs (a missing `+` between adjacent template literals) shipped to the live page: JS parses that as a **tagged template call**, so the first string is invoked as a function and the page dies with `"…" is not a function`. It is syntactically valid, so every syntax check passed. Two guards now exist and both must stay: `dodge/build.py` refuses to build when it sees adjacent template literals or markdown `**` inside a template literal (that one also shipped twice — the strings end up in `textContent`, so the asterisks show), and `node dodge/smoke_test.js` **executes** the render paths against the real result JSON. Verified by re-injecting the original bug: the smoke test fails with exit 1. CI (`.github/workflows/ci.yml`) runs both on every push.
- **JS number precision**: FlyWire root IDs (~7.2×10¹⁷) exceed 2^53. Always keep them as strings in JS — numeric literals silently lose precision and make ID lookups fail (this once produced a wrong conclusion that the water GRNs were absent from the subcircuit).

**v4 additions**:
- `game_core.js`: `launch(x, y, {strike: true})` aims at the fly's current position and stops there (`stopT`, removed after `hold` s). Lead aim now takes the earliest positive intercept root, so balls slower than walkSpeed (18 mm/s) are no longer aimed behind the fly; page speeds 35/60/95 are unaffected.
- `odorNav` (default off; page toggle "闻着找") is **hand-written, not connectome**: Gaussian odor field (σ 15 mm) sampled at two antennae, bang-bang 120°/s turn added to the DNa turn, touched pellets stop attracting. Feeding still goes through SUGAR/BITTER → MN9.
- `vnc/run_pugliese.py` calls the authors' `prepare_neuron_params` / `run_single_simulation` per replicate (their tutorial pattern) and scores rhythm with their `neuron_oscillation_score` (first 230 ms dropped, threshold 0.5; frequency ×1/dt → Hz). Relaxed tolerances were validated against defaults on 2 replicates (max rate diff 0.38 Hz, same frequency).
- `vnc/manc_full.py` keeps the authors' equation, sampling (`sample_trunc_normal` + `set_sizes`, imported) and Dopri5 settings but uses `jax.ops.segment_sum` on a sparse Wᵀ; the ODETerm is cached module-level so diffrax compiles once. `set_sizes` normalizes by the *network's* median size, so the same current is weaker in the full VNC: DNg100 needs I ≈ 350 (not 250) to reach the T1 default ~16 Hz; this calibration was declared before looking at rhythm.
- `vnc/proprio_loop.py` runs in `fba` with numpy RK4 (0.5 ms) because JAX and FlyGym 1.2.1 live in different envs; sensory neurons are clamped to hand-encoded rates each 1 ms. FlyGym 1.2.1 `obs["joints"][2]` torques are scaled ×1e-9 (≈1e-9 N·m), so print them in scientific notation.
- `vnc/drive_legs_pugliese.py` maps MANC `motor module` swing/stance pairs to ThC/CTr/FTi; joint directions come from FlyGym `PreprogrammedSteps` swing vs stance mean angles, target = stance extreme + u·(swing − stance extreme), u = r_swing/(r_swing + r_stance).

**Real-vision pipeline (`vision/`)**, offline only:
- FlyGym 1.2.1 `RealisticVisionFly` subclass `FastVisionFly` feeds a tethered fly looking at a mocap ball.
- Per-type arrays are indexed from `obs["nn_activities_arr"]`.
- FlyWire neurons get flyvis columns via Codex `column_assignment.csv.gz` (downloaded from `storage.googleapis.com/flywire-data/codex/data/fafb/783/`, no login) and PCA lattice alignment. All 8 axis orientations are run, because the true correspondence is unknown.
- Rates are baseline-subtracted, rectified, per-type 99.5th-percentile scaled, and fed through a Brian2 standalone `TimedArray` swapped via `device.run(run_args=...)` (one compile, 40 runs).

**FlyGym 2.1 API** (differs from 1.x tutorials and community code such as erojasoficial-byte/fly-brain):
- Setup: `make_locomotion_fly` → `fly.add_vision()` (must be called before `world.add_fly`) → `FlatGroundWorld` → `Simulation(world)`.
- Controllers come from `flygym_demo.complex_terrain`.
- Measured: descending signal `[1.2, 0.4]` (left stronger) turns the fly **right**.
- The default gray checker ground reads as "dark" (<0.2) to the retina; the demos recolor the `checker` texture to 0.85/0.95.

## Domain gotchas

- Neuron IDs are FlyWire v783 root IDs. The model's neuron table is `data/2025_Completeness_783.csv`, whose row order = model index. The annotation table has ~600 IDs not in the model; filter them out.
- The official notebook's left/right names for P9, DNa01, DNa02 and MN9 are the opposite of the annotation `side` field (soma side). New code uses annotation `side`; `run_experiment.py`'s `READOUT` dict keeps the notebook names.
- Directly stimulating photoreceptors (R1-6, R7, R8) drives no descending neurons in this LIF model (measured). Visual input must enter at visual projection neurons (LC4, LPLC2, LC10a…).
- Fly-Brain-AI turn-sign conflict (measured, 1 seed): `interfaces.py` and its paper draft say `turn_drive > 0` means right, and report "contralateral escape". But `LocomotionBridge` uses `left_scale = 1 - 0.3*max(0, turn_drive)`, so a positive value turns the body **left**. Left LPLC2 injection gave turn_drive ≈ +0.35 and a lateral offset of y ≈ +4 mm, i.e. turning toward the stimulated side. Confirm with multiple seeds plus the shuffled control before stating it as fact.
- Fly-Brain-AI's `behavior_summary` "turn=…deg" sums absolute per-frame heading changes. It is dominated by gait sway (~6000° in every condition) and says nothing about direction; use net lateral displacement or net heading from checkpoint positions instead. `--loom-rate-hz` has no effect, because `sensory_encoder.py` hard-codes LPLC2 max at 200 Hz. README says v4 readout has 389 neurons; the decoder JSON union is 350, and the missing 39 are unused by the decoder.
- Rendering jobs (FlyGym/MuJoCo OpenGL) launched as **background** tasks get throttled by macOS to ~10% CPU (18 min without finishing one stimulus); run them in the foreground in ≤10-min chunks. Pure-CPU jobs (node, Brian2) are fine in the background.
- flygym's stock `RealisticVisionFly` builds a flyvis `LayerActivity` every vision frame. Each one re-reads connectome h5 through `datamate`, which `sleep(0.1)`s on read failures, costing ~60% of runtime. Use `vision/flyvis_looming.py:FastVisionFly`; its output is verified identical.
- Step-2 result (pre-declared metric, mean rate 0.5–0.95 s):
  - LPLC2 looming > receding in 8/8 orientations and > far translation in 7/8, but < near translation in 0/8. So "looming > translation" only partly holds. **Revised 2026-09-19 (report §28.20/§28.20.1): those 8 orientations all sit on a DISTORTED lattice** — `normalize()` (PCA + per-axis std) stretches the Codex hex basis angle from 60.0 to 122.6 deg on both sides. With an anatomy-anchored, geometry-preserving mapping (anchor x0.6) the near-translation row FLIPS: looming > near translation in 3/3 repeats, the only one of ten mappings. Conditional revision, not a reversal — one mapping, n=3, ratio SD 0.24, higher input drive; keep both statements. With 3 repeats per condition (§18): 8/8/8, 8/7/8, 0/0/1 — the direction holds, and between-repeat SD (median 0.05 Hz) is 3–4× smaller than between-orientation SD (0.18 Hz), so the undocumented lattice alignment, not noise, dominates. Absolute rates are tiny (0.65 Hz looming vs 1.14 near translation).
  - The end-of-approach peak window was added after seeing curves; label it exploratory.
  - GF already fires ~30 Hz at baseline, from rectified noise of 44k injected inputs, so GF readouts in this pipeline are uninterpretable.

- What wiring alone can and cannot predict (§22, both hypotheses pre-declared): single-knockout effects are partly predictable from rate × signed 1–3-hop path sums, and better in the more concentrated pathway (water Spearman 0.45, 13/20 top hits; sugar 0.34, 9/20) — but signed direct synapses onto MN9 are useless in both (0.14 / −0.01) because the strongest hits have none. The redundancy hypothesis ("backup = disjoint paths to MN9, shared bottleneck = same path", cosine of path profiles) is **falsified**: Spearman with the pairing Δ is −0.008 (sugar) and 0.013 (water), and it is not a degenerate metric (max overlap 0.594/0.699; 83/312 sugar pairs and 99/204 water pairs have non-zero overlap; hub path profiles have 27/43 non-zero nodes; restricted to non-zero overlaps Spearman is −0.26 sugar / −0.04 water — a weak trace in the pre-declared direction on sugar only). So pair interactions — exactly what single knockouts cannot see — must be simulated. These degeneracy-check numbers used to be printed but not saved, and the report quoted wrong ones for months; `structure_vs_function.py` now writes them to `pairs.degeneracy_check` in the JSON.
- Dynamic fingerprints beat static wiring but do not replace the pair simulation (§22.1): cos(Δ(c), Δ(hub)) over whole-brain spike-count changes correlates −0.21 (sugar) / −0.14 (water) with the pairing Δ, in the pre-declared direction and an order of magnitude better than graph path overlap — but the partial correlation controlling for perturbation magnitude is only −0.13 / −0.21, and in water magnitude alone does better (0.47). The fingerprint is itself the single-knockout whole-brain simulation, so it saves screening, not the pair run. Segment files store counts for *all* neurons (not just the readout), so these fingerprints need no new simulations.
